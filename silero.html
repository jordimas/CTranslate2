Silero VAD v6 in CTranslate2

Branch silero-vad · target: Silero VAD v6 only (the version bundled by faster-whisper as silero_vad_v6.onnx). Older versions (v3/v4/v5) and the 8 kHz model are out of scope.

Architecture details below were read from the actual silero_vad_v6.onnx (opset 18, via the onnx package and shape inference) and ONNX Runtime. "Existing" columns come from reading include/ctranslate2/ops/ and layers/ on this branch. Nothing in CTranslate2 has been built or run yet.

1. Model architecture (v6, as exported)

Inputs: input [batch, 576], h [1, batch, 128], c [1, batch, 128]. Outputs: speech_probs (one probability per batch row), hn, cn. The 576 samples are a 512-sample chunk (32 ms at 16 kHz) with the previous 64 samples prepended as context; the context is managed by the caller (see faster-whisper's vad.py), not inside the graph. About 309k parameters, 1.2 MB in fp32.

 input [B, 576]   (64 context + 512 new samples)
   │
   ▼  [1] Pad, mode=reflect, 128 left + 128 right            -> [B, 832]
   ▼      Unsqueeze                                          -> [B, 1, 832]
   ▼  [2] Conv1d  1 → 258, k=256, stride=128, no bias        -> [B, 258, 5]
   │        weight = encoder.feature_extractor.forward_basis_buffer [258,1,256]  (constant)
   ▼  [3] Slice time [1:]  (drops first frame)               -> [B, 258, 4]
   │        real = ch 0..128, imag = ch 129..257
   │        magnitude = sqrt(real² + imag²)                  -> [B, 129, 4]
   ▼  [4] encoder (4 × Conv1d k=3 pad=1 + ReLU)
   │        129→128 s1  [B,128,4]
   │        128→ 64 s2  [B, 64,2]
   │         64→ 64 s2  [B, 64,1]
   │         64→128 s1  [B,128,1]
   ▼      Transpose                                          -> [B, 1, 128]
   ▼  [5] LSTM, 1 layer, hidden 128, input 128, (h, c) in/out
   ▼  [6] ReLU → Transpose → Conv1d 128→1 k=1 → Sigmoid      -> [B, 1]

Weights: conv_layers.{0..3}.{weight,bias} ([128,129,3], [64,128,3], [64,64,3], [128,64,3]), decoder.conv1d.{weight,bias} ([1,128,1]), LSTM W [1,512,128], R [1,512,128], B [1,1024] (input bias ‖ recurrent bias), and the STFT basis.

Resolved question: does the ONNX export fold the STFT into a constant? Yes — but in the simple way. The STFT is exported as a plain Conv node whose weight is the initializer encoder.feature_extractor.forward_basis_buffer, shape [258, 1, 256], fp32, values in [-1, 1]. It is already the windowed DFT basis (real rows then imaginary rows), so the converter receives it as an ordinary conv weight and needs no FFT or window code. The magnitude is exported as Slice → Pow(2) → Add → Sqrt. Two details the converter and layer must reproduce: the real part is channels 0–128 and the imaginary part 129–257, and the first of the 5 STFT frames is dropped by the Slice (so 4 frames feed the encoder). The weight can be taken from the ONNX file or the PyTorch buffer of the same name.

5. Artifacts to implement, grouped by PR

PR 1 — CPU ops: sqrt, Pad1D, LSTMCell

General-purpose ops, useful beyond VAD. No model code. Reviewable and mergeable on its own. Includes the C++ unit tests from A9 for these three ops (tests/primitives_test.cc, tests/ops_test.cc). Depends on: nothing.

A1. sqrt primitive

  • Files: declaration in include/ctranslate2/primitives.h; CPU implementation in src/cpu/primitives.cc (vectorized via vec.h where available); CUDA in src/cuda/primitives.cu.
  • Contract: Primitives<D>::sqrt(const T* x, T* y, dim_t size) for float (and half on GPU), same shape as the existing exp/log.
  • Test: a case in tests/primitives_test.cc.

A2. ops::Pad1D (reflect)

  • Files: include/ctranslate2/ops/pad.h, src/ops/pad.cc (dispatch), src/ops/pad_cpu.cc, optional pad_gpu.cu; register in ops/ops.h.
  • Contract: Pad1D(left, right, mode), input [batch, length] or [batch, channels, length], output length + left + right. Reflect mode excludes the edge sample (PyTorch/ONNX semantics: index -i → i). Requires left, right < length.
  • Test: tests/ops_test.cc against hand-computed examples, including 128/128 on length 576.

A3. ops::LSTMCell

  • Files: include/ctranslate2/ops/lstm_cell.h, src/ops/lstm_cell.cc, CPU loop, optional lstm_cell_gpu.cu.
  • Contract: (x[B,I], h[B,H], c[B,H], W_ih[4H,I], W_hh[4H,H], bias[4H]) → (h', c'). Computes gates = x·W_ihᵀ + h·W_hhᵀ + bias, splits into 4 gates, applies sigmoid to input/forget/output, tanh to cell, then c' = f·c + i·g, h' = o·tanh(c').
  • Gate order: pick CTranslate2's convention (PyTorch order: i, f, g, o) and convert in the converter; the ONNX file uses i, o, f, c.
  • Implementation: gemms via the existing Gemm, then one fused elementwise pass for gates and state update. A composed reference (from existing ops) lives only in the unit test, to check the fused result.

PR 2 — Python spec and converter

Defines the model format and produces a CT2 model directory from the official ONNX file. Includes the converter test from A9 (expected variables, gate reorder, bias sum, STFT basis shape) using a tiny random-weight model with the same topology. Depends on: nothing at runtime; PR 3 consumes its output.

A7. Python spec and converter

  • Files: python/ctranslate2/specs/silero_vad_spec.py (export in specs/__init__.py), converter python/ctranslate2/converters/silero_vad.py (export in converters/__init__.py) with CLI entry ct2-silero-vad-converter.
  • Spec: LayerSpec tree matching the layer, with variables for the STFT basis, 4 conv blocks, LSTM (weight_ih, weight_hh, bias), and decoder conv. Revision and config fields (sample_rate=16000, chunk_size=512, context_size=64).
  • Converter input: the official ONNX file (read with the onnx package) or the PyTorch checkpoint. Steps: read initializers by name, reorder LSTM gates from ONNX i,o,f,c to the chosen order, sum the two bias halves (B[:512] + B[512:]), squeeze the leading dimension of W/R, and store the STFT basis as a normal conv weight. Quantization is not applicable (keep fp32; allow fp16 only for GPU).
  • Output: a CT2 model directory (model.bin, config.json).

PR 3 — Layer, model and Python bindings (the feature)

Wires PR 1 ops into the encoder layer and exposes it. After this PR, VAD works end to end on CPU. Includes the end-to-end tests from A9: match ONNX Runtime to ~1e-5 on silence, noise, speech, multi-chunk streaming, batch 1 and >1. Depends on: PR 1 and PR 2.

A5. Layer layers::SileroVADEncoder

  • Files: include/ctranslate2/layers/silero_vad.h, src/layers/silero_vad.cc (add to CMakeLists.txt).
  • Owns: the STFT conv weight, four encoder conv weight/bias pairs, LSTM weights, decoder conv. Looks them up by scope name from the model variables.
  • Forward: (audio[B,576], StreamState&) → probs[B] running stages [1]–[6] exactly as in section 1.
  • State: a StreamState struct with h, c [B,128] and a context [B,64] buffer. The layer builds the 576-sample input from the stored context plus 512 new samples and updates the context to the last 64 samples.

A6. Model models::SileroVADModel and replica

  • Files: include/ctranslate2/models/silero_vad.h, src/models/silero_vad.cc; register in the model factory (spec name SileroVADSpec).
  • API: SileroVAD class (like Wav2Vec2) built on ReplicaPool, with compute_type and device selection. Methods: predict(chunk_batch, state) and a convenience predict_audio(samples) that chunks a full waveform in 512-sample steps, carrying state, and returns one probability per chunk.
  • Decision: state is held by the caller (explicit, thread-safe, supports many streams) rather than inside the model.

A8. Python bindings

  • Files: python/cpp/silero_vad.cc, registered in python/cpp/module.cc and python/CMakeLists.txt.
  • API: ctranslate2.models.SileroVAD(model_path, device="cpu", ...) with __call__(audio_chunks, state=None) returning probabilities and the new state, plus predict_audio(waveform). NumPy in/out and GIL released during compute.

PR 4 — Post-processing helper

Pure-Python speech-segment extraction. No C++ changes. Unit tests on synthetic probability sequences (hysteresis, min durations, padding, max length). Depends on: PR 3 for the API, though it can be developed in parallel.

A11. Post-processing helper (Python)

  • Turns per-chunk probabilities into speech segments: threshold (with a lower negative threshold for hysteresis), minimum speech duration, minimum silence duration, speech padding, max segment length. Mirrors faster-whisper's get_speech_timestamps; lives in python/ctranslate2/ as a pure-Python utility so it does not affect the C++ core.

PR 5 — Performance and other backends (optional)

Only if profiling or GPU co-location shows a need. Each kernel gets a test comparing against the CPU result. Depends on: PR 1 and PR 3.

A4. Optional fused stft_magnitude

  • Input: STFT conv output [B, 258, 5]. Output: [B, 129, 4], sqrt(re² + im²), frame 0 dropped. Replaces Slide + Split + Mul + Mul + Add + sqrt (6 launches) with one. Skip until numerics are correct.

A10. Optional GPU / MPS kernels

  • sqrt in src/cuda/primitives.cu; pad_gpu.cu; lstm_cell_gpu.cu; MPS variants as .mm files. Only worthwhile to avoid host copies when running next to Whisper on GPU.

6. Merge order

  1. PR 1 and PR 2 in parallel (independent).
  2. PR 3 after both. First milestone: single-chunk match with ONNX Runtime, then multi-chunk streaming.
  3. PR 4 once the PR 3 API is stable.
  4. PR 5 last, and only if needed.

7. Remaining risks and open questions

  • Batched streams need per-stream state; the exported graph already takes h, c as [1, B, 128], so the layer should too. Check that the ONNX output really is one probability per row for B > 1 (the Reshape flattens it).
  • Per-chunk latency is dominated by kernel launches, not FLOPs; the fused CPU path is the performance target.
  • Reflect padding with 128 on each side of a 576-sample row only works because 128 < 576; the op should validate this.
  • Licensing: the Silero VAD weights are MIT-licensed; the converter should fetch or accept the file rather than ship it in the repo.
